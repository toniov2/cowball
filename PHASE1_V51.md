# Cowball v51 — Фаза 1 (каркас)

Запуск: `npm ci` → `npm run dev` (разработка) / `npm test` (typecheck + lint + 25 unit + build + 6 e2e). Сборка: `npm run build` → `dist/` (его и публикует CI на Pages).
E2E в песочнице: `CHROMIUM_PATH=/путь/к/chrome npx playwright test`.

## Принцип
Старые файлы не переименованы и работают как раньше (классические скрипты). Vite собирает только новый код `src/` в `cowball-v2.js` (+ воркер `assets/sim.worker.js`), остальное копирует в `dist/` как есть. Реальный Three.js r128 берётся из devDependencies и кладётся в `dist/three.min.js` (CDN больше не нужен в сборке). В ядро добавлены **4 точечные вставки** (мост `window.CowballV2Hook`): рендерер, `setState`, `save()` ×3 места.

## НЕ сделано / НЕ проверено (честно)
- **«Пустое поле 60 FPS» не подтверждено.** В песочнице только программный GL (SwiftShader): ~0.6 FPS на меню, это цифра среды, не игры. Нужен замер на реальном телефоне/ПК: открой игру и вызови в консоли `Cowball2.perf.snapshot()`.
- **Ядро по-прежнему один файл ~930 КБ с обёртками** (`Audio_.crowd` ×3 и т.д.). Разбор на ES-модули и замена обёрток автоматом состояний НЕ сделаны: без этого риск сломать геймплей вслепую. FSM пока только наблюдает; строгая таблица переходов не включена (нужно набрать реальные переходы игрой).
- **Физика и ИИ в воркерах не сделаны**: их код живёт в ядре; воркер-инфраструктура готова, переносить логику — Фаза 3. В воркере сейчас только симуляция турниров.
- **Геймплейный ГСЧ**: ~110 `Math.random()` в ядре остались, фиксированный шаг в самой игре не включён (модуль готов и протестирован отдельно). Один матч с одним зерном пока не воспроизводится.
- Zod-схема проверяет только основные поля; остальные ключи проходят без проверки. IndexedDB — зеркало, основное хранилище по-прежнему localStorage.
- i18next не подключён к строкам ядра (сотни русских строк в коде).
- Не проверены: офлайн-режим с новым `cowball-v2.js`, CI на GitHub, Safari/Firefox, реальный телефон, 3D на глаз.
